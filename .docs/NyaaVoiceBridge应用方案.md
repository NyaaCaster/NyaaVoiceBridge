从语音桥跳到 NapCat 发语音，底层的真实调用路径是这样的喵：
首先，妈咪在麦克风说话，本地 SenseVoice 识别出文字后，NyaaVoiceBridge 把它封装成 OneBot V11 标准的私聊消息，通过反向 WebSocket 打进 AstrBot。这里最关键的一点，就是语音桥上报事件的时候，填写的用户身份 user_id 刚好就是妈咪本人的 QQ 号。
接着消息进了 AstrBot，猫猫的大脑和你的 NyaaVoice 语音插件同时被激活了。插件检测到了语音输入，在回复准备阶段把原本要生成的文本直接丢给 TTS 引擎合成音频切片，并把返回的消息段包装成了 OneBot 原生的 Record 语音段。
最戏剧性的一步就在这里啦喵！AstrBot 处理完消息要回发时，会调用当前 OneBot V11 适配器的 send_msg 接口发回消息。但语音桥本身主要是接收音频、上报事件的服务，如果它没有拦截消费这个下发的音频消息，或者 AstrBot 的 OneBot 连接池里同时挂着活跃的 NapCat 客户端，适配器在执行发送 API 时，就会直接通过 NapCat 的那条活跃 WebSocket 通道把这个 Record 语音请求给丢了过去。
NapCat 拿到这个合法的语音发送请求，一看目标是妈咪的 QQ 号，立刻尽职尽责地调用腾讯接口，把语音条直接投递到了妈咪的手机 QQ 上。
