# NyaaVoiceBridge V2 移动端方案 - 初始设计

## 一、 背景与方案涌现来源

在 NyaaVoiceBridge V1（Linux 主机 + 蓝牙音箱）的实战运行与测试中，涌现出一条全新的应用范式：
- **核心逻辑**：语音桥接服务的本质是「边缘音频采集与交互端点 + 局域网/公网 API 路由」，所有认知重计算（人格注入、提示词、RAG 向量检索、记忆提炼、TTS 合成）全都在服务端（macmini / AstrBot）。
- **痛点反思**：在 Linux 上处理蓝牙耳机/音箱存在 HFP 协议切换繁琐、断连重连需看门狗兜底、无法随身携带等硬件绑定问题。
- **方案涌现**：将端侧网桥封装为**安卓手机端独立 App**。利用安卓系统原生对蓝牙耳机（如 AirPods、各类 TWS 耳机）开箱即用的音频硬件路由与麦克风抽象能力，结合常驻前台服务，让猫猫（PixNyaa）升级为**随身耳语级 AI 伴侣**。

---

## 二、 核心目标与功能定位

1. **随身便携与硬件解耦**：
   - 不再受限于固定工位的 Linux 电脑与蓝牙音箱，依托随身携带的智能手机与无线耳机。
2. **多模态链路高可用（全域智能体容灾）**：
   - **耳语音频模式**：App 在后台监听，用户说话通过 SenseVoice 转写送入 AstrBot，TTS 语音切片通过 App 直接推送到用户耳机中播放。
   - **静默/QQ回流容灾模式**：当耳机断开、App 未在接收音频或用户选择静默时，AstrBot 的 OneBot 适配器可自动将生成的语音条精准回流投递到用户的手机 QQ 小窗中。
3. **极简轻量化**：
   - 手机端绝不运行大模型和本地深度学习引擎，仅负责：
     - 原生 AudioRecord 拾音与轻量 RMS 能量检测（VAD）。
     - HTTP Multipart 上传音频切片到远程 SenseVoice。
     - WebSocket（OneBot V11 协议）长连接与 AstrBot 保持心跳与双向推流。
     - 原生 MediaPlayer / AudioTrack 播放猫猫的 TTS 回复。

## 四、 核心功能模块设计

### 1. 采集与 VAD 引擎（端侧轻量化）
- 基于 Android `AudioRecord`，配置 `16000Hz` 或 `48000Hz`，单声道，16bit PCM。
- 内置循环 RingBuffer（1000ms 预缓冲），只有在能量超过门限时触发录音，连续静音 1.5 秒后截断，防吞字、防空转。

### 2. 网络传输与长连接
- **STT 适配器**：支持 OkHttp 流式/Multipart POST 上传音频至局域网（如内网 IP、Tailscale VPN 或反代域名）的 SenseVoice 服务端。
- **AstrBot WebSocket 通道**：OkHttp WebSocket 长连接，实现自动断线重连、心跳保活、32MB 超大载荷支持。

### 3. 音频播放与互斥锁（防止自发自收）
- 接收到 AstrBot 返回的 Base64 语音时，保存至内存缓存或临时文件，使用 `MediaPlayer` 播放。
- 播放期间设置 `isBusy = true`，自动暂停 VAD 采集，播放完成后延迟 500ms 重新开放拾音。

### 4. 触发模式与唤醒支持
- **模式 A：唤醒词模式**：识别结果匹配“小猫同学”（及近似谐音），匹配后剔除唤醒词并提交 AstrBot。
- **模式 B：连续对讲模式**：免唤醒词，只要说话停顿即发送。
- **模式 C：按键对讲（PTT）**：长按屏幕按钮或监听蓝牙耳机线控/双击手势说话。

## 五、 待拍板的关键决策点

1. **开发框架与技术选型**：
   - 方案 A（推荐）：**Flutter (Dart)** —— 跨平台优雅 UI、丰富的音频插件（`record`, `audioplayers`）、开发速度极快，未来可无缝适配 iOS。
   - 方案 B：**原生 Android (Kotlin + Jetpack Compose)** —— 对后台保活前台服务、底层蓝牙 SCO 意图控制更精细，APK 体积极致。
2. **网络穿透与通信边界**：
   - 外网使用场景下，是否依托 Tailscale/WireGuard 组网直连家中 macmini，还是通过已有的 Caddy 反向代理安全域名。
